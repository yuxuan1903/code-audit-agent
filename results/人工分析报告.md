## 二、逐条分析

### 2.1 三条走了对抗验证的（`require_adversarial_for: [CRITICAL, HIGH]`）

只有这三条触发了强制对抗验证，与配置一致。**但三条都没拿到验证者的结论**——验证者各用满 8 轮（`max_turns` 默认值，由 Agent 在工具调用里给）未提交 `submit_verdict`，引擎按 `verify.py:235-239` 兜底判 `NEEDS_HUMAN`。所以下面三条的「验证」栏是空的，我的核对补上了这一课。

#### F-003 CRITICAL — XML-RPC `delete_all_topic` 只认证不鉴权

**主张**：任意注册用户可删除全站主题。

**原文核对**（我逐行读的靶子源码）：

```python
60  def delete_all_topic(user, passwd):
61      '''delete all topic'''
62      if not has_auth(user, passwd):
63          raise Fault(-1, "Authentication Failure")
64
65      try:
66          Topic.objects.all().delete()
67          return True
```

- 位置、函数名、行为**逐字一致**：66 行确实是全表删除。
- `has_auth` 在 39-45 行，函数体只调 `authenticate()`，**没有 `is_active` / `is_superuser` / 归属判断**。
- 同文件 `delete_topic`（47-58）、`edit_topic`（168-185）同样是「只认证 + 按 pk 取对象 + 无归属校验」。
- 入口可达性：`settings.py` 的 `XMLRPC_METHODS` 暴露了写操作接口，与报告所述一致。

**我的判断**：**这是本次运行最有价值的一条，且我核到的事实比报告写的更硬。** 报告把它标为 `NEEDS_HUMAN` 而非 `CONFIRMED` 是对的——「任意注册用户」这个前提取决于部署层（是否所有注册用户都能过 `authenticate`、网关是否另设限制），那不在代码里。但**「代码层没有对象级授权」这一点是确定的**，不是推测。

#### F-001 HIGH — 帖子正文未转义即 `|safe` 渲染

**主张**：`Post.save()` 在 `markup == 'none'` 分支不转义正文，模板却用 `|safe`，构成存储型 XSS。

这条的链条比 F-003 长，我核了**每一环**：

| 环 | 原文 | 结果 |
|---|---|---|
| 1. 分支不转义 | `models.py:256` 是 `Markdown(self.body, safe_mode='escape')`（安全的那支）；`:258 elif self.markup == 'none':`；`:260` 是 `Markdown(extensions=['fenced_code']).convert(ylinux_text_filter(self.body))`——**没有 `safe_mode='escape'`** | ✅ |
| 2. `ylinux_text_filter` 是否补了转义 | 定义在 `app/ydata/models.py:396`，函数体做的是附件引用替换（`ATTACHMENT_QUOTE` 匹配 → 查 `Attachment` → 拼 HTML），**不是 HTML 转义** | ✅ 不转义 |
| 3. 出口是否 `|safe` | 6 个模板出现 `{{ ... body_html|safe }}`，含 `templates/bbs/topic.html:23` 与 `:30`、`templates/wiki/post.html:12` | ✅ |

**我的判断**：**链条成立**；报告的 `sanitizer_check` 也自己枚举了 4 个候选净化点并逐一排除，与我核到的一致。

**残余不确定性**：`markup` 字段由发帖表单决定，我**没有核表单**（本轮未读发帖视图与表单）。若普通用户不能把 `markup` 置为 `'none'`，链条的第一环就要重来。这是这条唯一没关掉的口子。

#### F-002 HIGH — `/lab/update_post_profile` 无鉴权全表改写

**主张**：无鉴权入口，改写全部帖子的 `touser` / `updated`。

**原文核对**：

```python
37  def update_post_profile(req):
38
39      posts = Post.objects.all()
40      for p in posts:
41          if p.parent: p.touser = p.parent.user
44          else:        p.touser = p.topic.user
45          p.updated = p.created
46          p.save()
48      return HttpResponse(u'更新 posts 完成!')
```

- 函数体**逐字一致**：全表遍历 + `save()`，无任何权限判断、无装饰器。
- 路由：根 `urls.py:31` → `^lab/` include → `app/ylab/urls.py:8` `^update_post_profile$`，确认可外部触达。
- 「无鉴权」的前提：`settings.py:98-103` 的 `MIDDLEWARE_CLASSES` 只挂 `CommonMiddleware` + 自定义 `SessionMiddleware` + 自定义 `AuthenticationMiddleware`；后者（`app/account/middleware.py:15-19`）只 `assert hasattr(request,'session')` 然后设 `request.user`，**不强制登录、不重定向**。

**我的判断**：**「未认证即可触达」成立。** 一个 GET 请求即可触发全表写——这不是「信息泄露」级别，是**可被任意人调用的数据破坏入口**。报告给 HIGH 是合理的。

**一个补充**：这个视图同时是 `C1` 的载体但它没走 CSRF——见 F-009。
